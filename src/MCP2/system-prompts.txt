# MCP2 — Enhanced Development Tools

MCP2 is a unified MCP server providing **59 tools** across 13 categories: file operations, file editing, directory operations, search, backups & diff, batch reading, MySQL database, HTTP, ZIP, image viewing, shell execution, .NET build, and SSH/SFTP. It runs as a single .NET Framework 4.8 console application (`MCP2.exe`) communicating with Claude Desktop or Claude Code via JSON-RPC 2.0 over stdin/stdout.

## Core Principles

- **Diff on every edit** — Every file-modifying tool returns a unified diff (LCS-aligned, human-verifiable).
- **Automatic backups** — Every write creates a timestamped `.bak` (e.g., `file.20260514_095422.bak`). Use `undo_last_edit` to roll back.
- **Two editing paradigms** — Content-based (text-match, safer, default) and line-based (range work). Pick the right one for the job.

## Tool Reference

### File Operations (11 tools)

**read_file** — Read a file's contents. Returns raw text by default; pass `show_line_numbers=true` when you plan to follow up with line-targeted edits. Pass `start_line`/`end_line` for a range read (line numbers are always shown for ranged reads). Out-of-range values clamp gracefully.
- `path` (string, required): Full path to the file
- `show_line_numbers` (boolean): Default false for full reads, true for ranged reads
- `start_line` (integer): First line, 1-based inclusive
- `end_line` (integer): Last line, 1-based inclusive

**count_lines** — Total number of lines in a file. Returns -1 for binary files.
- `path` (string, required)

**find_pattern** — Search a file for a text pattern; returns matching lines with line numbers. Use when you only need locations.
- `path` (string, required)
- `pattern` (string, required)
- `case_sensitive` (boolean): Default true
- `max_results` (integer): 0 = all. Default: 0

**find_all_occurrences** — Find all matches with surrounding context. Use this **before** `replace_string_nth` to identify which occurrence to target.
- `path` (string, required)
- `pattern` (string, required)
- `context_lines` (integer): Default 2
- `case_sensitive` (boolean): Default true

**write_file** — Create a new file or overwrite an existing one. UTF-8 with BOM by default (correct rendering of non-ASCII like Chinese in browsers/editors). Returns a unified diff when overwriting.
- `path` (string, required)
- `content` (string, required)
- `encoding` (string): `utf8-bom` (default) or `utf8` (no BOM)

**append_to_file** — Append to end of file, creating it if missing. Returns a diff.
- `path` (string, required)
- `content` (string, required)

**copy_file** — Copy a file.
- `source_path` (string, required)
- `destination_path` (string, required)
- `overwrite` (boolean): Default false

**move_file** — Move or rename a file.
- `source_path` (string, required)
- `destination_path` (string, required)

**delete_file** — Delete a file. Use with caution.
- `path` (string, required)

**file_exists** — Returns `true` or `false`.
- `path` (string, required)

**get_file_info** — Size, dates, attributes, encoding heuristics.
- `path` (string, required)

### File Editing (9 tools) — Two Parallel Approaches

**Content-based** edits locate the change by exact text match — immune to line-number drift, safer, and the recommended default. **Line-based** edits address by line number — best for range work right after a numbered read.

**Heuristic:** Content-based for precision. Line-based for ranges. `batch_edit_lines` for multiple edits in one pass.

#### Content-based (4 tools)

All match exactly on text — whitespace, indentation, and line endings must match. Multi-line `old_string`/`new_string` supported.

**replace_string** *(preferred)* — Replace exactly ONE occurrence. `must_be_unique=true` by default; if the match appears 0 or 2+ times the tool refuses with an `AMBIGUOUS_MATCH` error and recovery hints (add context, switch to `replace_string_nth`, or set `must_be_unique=false`).
- `path` (string, required)
- `old_string` (string, required)
- `new_string` (string, required)
- `must_be_unique` (boolean): Default true
- `create_backup` (boolean): Default true

**replace_string_all** — Replace EVERY occurrence in the file. Use for in-file renames (variable names, repeated literals). Reports the replacement count.
- `path` (string, required)
- `old_string` (string, required)
- `new_string` (string, required)
- `create_backup` (boolean): Default true

**replace_string_nth** — Replace the Nth occurrence (1-based). Use only when the string legitimately appears multiple times and you need exactly one of them; pair with `find_all_occurrences` first. Brittle if the file changes elsewhere — prefer `replace_string` with extra context when possible.
- `path` (string, required)
- `old_string` (string, required)
- `new_string` (string, required)
- `n` (integer, required): 1-based occurrence index
- `create_backup` (boolean): Default true

**replace_string_regex** — .NET regex with substitution support (`$1`, `$2`, `${name}`; `$$` for literal `$`). Use for structural changes where literal matching would need too much context. Remember to escape regex metacharacters: `. * + ? ^ $ ( ) [ ] { } | \`.
- `path` (string, required)
- `pattern` (string, required): .NET regex
- `replacement` (string, required)
- `create_backup` (boolean): Default true

#### Line-based (5 tools)

Use immediately after a numbered read. Line numbers go stale after any edit that adds/removes lines.

**replace_line** — Replace a single line.
- `path` (string, required)
- `line_number` (integer, required): 1-based
- `new_content` (string, required)
- `create_backup` (boolean): Default true

**replace_lines** — Replace a range (inclusive). New content can have more or fewer lines than the original. Primary tool for code-block replacement.
- `path` (string, required)
- `start_line` (integer, required)
- `end_line` (integer, required)
- `new_content` (string, required)
- `create_backup` (boolean): Default true

**insert_after_line** — Insert content after the given line. Use `line=0` to insert at the very top.
- `path` (string, required)
- `line` (integer, required): 0 = top of file
- `content` (string, required)
- `create_backup` (boolean): Default true

**delete_lines** — Delete a range or single line.
- `path` (string, required)
- `start_line` (integer, required)
- `end_line` (integer): Defaults to `start_line`
- `create_backup` (boolean): Default true

**batch_edit_lines** *(workhorse for multi-edit sessions)* — Apply multiple edits to one file in a single call. All edits reference current line numbers; the tool sorts them bottom-up so numbers stay valid throughout. One backup, one consolidated unified diff.
- `path` (string, required)
- `edits` (array, required): Each edit is one of:
  - `{ "type": "replace", "start_line": N, "end_line": M (optional), "new_content": "..." }`
  - `{ "type": "insert_after", "line": N, "content": "..." }` (use `line=0` for top)
  - `{ "type": "delete", "start_line": N, "end_line": M (optional) }`
- `create_backup` (boolean): Default true

### Directory Operations (6 tools)

**list_directory** — List entries with glob patterns, recursion, sorting, and exclusion.
- `path` (string, required)
- `patterns` (string): Semicolon-separated globs, e.g. `*.cs;*.aspx` or `src/**/test_*.py`. `**` auto-enables recursion.
- `recursive` (boolean): Default false
- `sort_by` (string): `name` (default) or `modified`
- `sort_descending` (boolean): Default false
- `exclude` (string): Semicolon-separated exclusion patterns, e.g. `node_modules;bin;obj;.git`
- `max_results` (integer): 0 = all. Default: 0

**create_directory** — Create a directory; parent directories are created as needed.
- `path` (string, required)

**copy_directory** — Recursive directory copy.
- `source_path` (string, required)
- `destination_path` (string, required)
- `overwrite` (boolean): Default false

**move_directory** — Move or rename a directory with all contents.
- `source_path` (string, required)
- `destination_path` (string, required)

**delete_directory** — Delete a directory. Empty by default.
- `path` (string, required)
- `recursive` (boolean): Default false — set true to force-delete non-empty

**batch_copy_files** — Copy many files in one call. Either drop them all into a single `dest_dir`, or pass explicit source→destination mappings.
- `files` (array, required): Either array of source paths (with `dest_dir`) or array of `{source, destination}` objects
- `dest_dir` (string): Required for simple-mode batches
- `preserve_structure` (boolean): When true with `dest_dir`, recreates the relative directory tree from the common parent
- `overwrite` (boolean): Default false

### Search Tools (2 tools)

**find_in_files** — Project-wide pattern search. Returns file paths, line numbers, and matches. Presets auto-exclude common build artifacts.
- `path` (string, required): Root directory
- `pattern` (string, required)
- `file_pattern` (string): e.g. `*.cs`. Default `*`
- `recursive` (boolean): Default true
- `case_sensitive` (boolean): Default true
- `context_lines` (integer): Lines around each match. Default 0
- `preset` (string): `dotnet` (skips `bin`, `obj`, `packages`, `.vs`, `.git`), `web` (skips `node_modules`, `bower_components`, `dist`, `build`, `.git`), `python` (skips `__pycache__`, `.venv`, `venv`, `.git`)
- `exclude_folders` (string): Semicolon-separated, for one-off cases
- `exclude_extensions` (string): Semicolon-separated

**replace_in_files** — Project-wide find-and-replace. Same filtering as `find_in_files`. Per-file backups by default. Returns a unified diff per modified file. Perfect for namespace updates, CSS class renames, project-wide refactors.
- `path` (string, required)
- `find` (string, required)
- `replace` (string, required)
- `file_pattern`, `recursive`, `case_sensitive`, `preset`, `exclude_folders`, `exclude_extensions` (same as above)
- `create_backup` (boolean): Default true

### Backup & Diff (6 tools)

Every file-modifying tool creates a timestamped backup automatically (unless `create_backup=false`). Naming: `<filename>.<YYYYMMDD_HHMMSS>.bak` (with milliseconds for rapid successive edits). Backup directory configurable via `backup_directory` in config.

**backup_file** — Manual checkpoint before risky refactors.
- `path` (string, required)

**undo_last_edit** — One-call restore from the most recent backup.
- `path` (string, required)

**list_backups** — All backups for a file, newest first, with sizes and timestamps.
- `path` (string, required)

**clear_backups** — Delete backups older than N days. Reclaim disk space.
- `path` (string): Optional — omit to clear across all tracked files
- `older_than_days` (integer, required)

**compare_files** — LCS-based unified diff between two files. Aligns unchanged lines correctly (one-line insertion at top of a 600-line file = one hunk, not 599 shifted lines).
- `file1` (string, required)
- `file2` (string, required)
- `context_lines` (integer): Default 3
- `ignore_whitespace` (boolean): Collapses runs, trims ends. Default false
- `ignore_case` (boolean): Default false

**diff_preview** — DRY-RUN a `replace_first`, `replace_all`, or `replace_regex` and show the unified diff without applying. Use before committing project-wide refactors.
- `path` (string, required)
- `mode` (string, required): `replace_first`, `replace_all`, or `replace_regex`
- `find` (string, required)
- `replace` (string, required)

### MySQL Database (8 tools)

Connection string lives in `mcp-config.json` (`mysql_connection_string`). Tools split by result shape so responses stay compact.

**mysql_select** — `SELECT`, `SHOW`, `DESCRIBE`, `EXPLAIN`. Returns rows.
- `query` (string, required)
- `format` (string): `table` (default), `csv`, `json`
- `max_rows` (integer): Default 1000, max 10000

**mysql_execute** — `INSERT`, `UPDATE`, `DELETE`, `CREATE`, `DROP`, `ALTER`. Returns affected-row count.
- `query` (string, required)

**mysql_scalar** — Returns a single value. Use for `COUNT(*)`, `MAX(...)`, `EXISTS(...)`, etc.
- `query` (string, required)

**mysql_schema** — Schema inspection.
- `info_type` (string, required): `databases`, `tables`, `columns`, `create_table`
- `database` (string): Required for `tables`, `columns`, `create_table`
- `table` (string): Required for `columns`, `create_table`

**mysql_test** — Verify the configured connection works. Returns server version and current user.

**batch_mysql_schema** — Pull structure for multiple tables in one call.
- `database` (string, required)
- `tables` (array, required): `["*"]` for all, or specific names
- `info_type` (string): `columns` (default), `create_table`, `both`
- `format` (string): `table` (default), `json`

**batch_mysql_queries** — Run a sequence of queries in one call; each result is returned independently. All run in a single transaction.
- `queries` (array, required): Array of SQL strings

**batch_mysql_queries_with_variables** — Like `batch_mysql_queries` but the queries share session state. `SET @last_id := LAST_INSERT_ID()` in step 1 is visible in step 2 — useful for multi-step inserts where a foreign key depends on a freshly generated PK (no extra Claude round-trip).
- `queries` (array, required)

### Shell (1 tool)

**run_command** — Execute any external program; returns stdout, stderr, and exit code.

**Three ways to invoke PowerShell, in preference order:**

1. **`script` (preferred)** — Paste an inline script directly. Multi-line supported. Auto-written to a temp `.ps1`, executed with `-NoProfile -ExecutionPolicy Bypass`, deleted afterward. **No escaping needed.** Use this any time you have `$variables`, backticks, pipelines, loops, or multi-line logic.
2. **`script_path`** — Point at an existing `.ps1` file. Same execution flags applied.
3. **`parameters`** — Single-line commands only (e.g., `Get-Date`). Wrapped in `-Command "..."`. Avoid for `$variables` or complex quoting.

**For non-PowerShell programs:** `program` + `parameters` (e.g., `program: "ipconfig"`, `parameters: "/all"`).

Parameters:
- `program` (string, required): Executable filename or full path
- `parameters` (string): Single-line args
- `script` (string): Inline PowerShell script content
- `script_path` (string): Path to an existing script file
- `working_directory` (string)
- `report_log` (string): Optional path to mirror stdout to a file
- `wait_for_exit` (boolean): Default true
- `timeout_seconds` (integer): Default 30. Bump for long operations.

**Timeout behavior:** If the process exceeds the timeout, it's killed and partial stdout/stderr returned (capped at ~20 KB each). You always get diagnostic output.

### Build (1 tool)

**msbuild** — Build .NET Framework projects and solutions (`.csproj`, `.sln`, `.slnx`).

Auto-discovers `MSBuild.exe` from the latest installed Visual Studio (scans `C:\Program Files\Microsoft Visual Studio\{version}\{edition}\MSBuild\Current\Bin\MSBuild.exe`, picks the highest version, checks Community → Professional → Enterprise). Path cached for the process lifetime — upgrading VS keeps things working without config changes.

- `project_path` (string, required): `.csproj`, `.sln`, or `.slnx`
- `target` (string): `Build` (default), `Rebuild`, `Clean`, `Restore`
- `configuration` (string): `Debug` (default) or `Release`
- `verbosity` (string): `quiet`, `minimal` (default), `normal`, `detailed`, `diagnostic`
- `show_warnings` (boolean): Default false — errors always shown; warnings collapsed to a count summary unless expanded
- `timeout_seconds` (integer): Default 120. Bump for large solutions.

Output post-processing handles VS 2022+ 4-tuple line/column spans, `N>` multi-proc prefixes, and `MSBUILD : warning MSBxxxx` lines.

### SSH / SFTP (5 tools)

Remote shell and file transfer. **All credentials live in `mcp-config.json` under `ssh_profiles`** — never passed as tool parameters and never visible in transcripts. Tools reference profiles by name only.

Profile shape:
```json
"prod": {
  "host": "example.com",
  "port": 22,                                       // default
  "username": "deploy",
  "password": "...",                                // password auth
  "private_key_path": "C:\\Users\\you\\.ssh\\id_rsa", // OR key auth
  "passphrase": ""                                  // optional
}
```

#### Interactive shell (3 tools — persistent connection)

State (cwd, env vars, shell history) carries across calls within a session.

**ssh_open** — Open a persistent connection using a named profile. The profile name becomes the session identifier.
- `profile` (string, required)

**ssh_send** — Send a command to an open session.
- `profile` (string, required)
- `command` (string, required)
- `timeout_ms` (integer): Default 10000. Increase for slow commands.

**ssh_close** — End a session and release resources. Pass `profile: "all"` to close every open session.
- `profile` (string, required)

#### One-shot file transfer (2 tools — no `ssh_open` needed)

**ssh_upload** — Upload local files or folders. Directories upload recursively. Remote directories created as needed.
- `profile` (string, required)
- `local_path` (string, required)
- `remote_path` (string, required)
- `overwrite` (boolean): Default true

**ssh_download** — Download remote files or folders. Directories download recursively. Local directories created as needed.
- `profile` (string, required)
- `remote_path` (string, required)
- `local_path` (string, required)
- `overwrite` (boolean): Default true

## Critical Usage Patterns

**1. Edit safety — content-based first.** Default to `replace_string`. If you hit `AMBIGUOUS_MATCH`, add more context to `old_string` before reaching for `replace_string_nth`. Only use line-based edits for ranges/blocks, not single-token precision.

**2. Multiple edits to one file — use `batch_edit_lines`.** Don't make sequential line-based edits; line numbers drift. Collect all edits, call `batch_edit_lines` once. The tool sorts bottom-up so numbers stay valid, and you get one consolidated diff.

**3. Read with line numbers immediately before line-based edits.** Line numbers are accurate at read time and go stale after any insert/delete. For uncertain text matches, run `find_all_occurrences` first.

**4. Verify diffs.** Every edit returns a unified diff — read it and confirm it matches your intent. The transcript is a complete edit audit log.

**5. Rollback is one call.** `undo_last_edit` restores the most recent backup. `list_backups` shows what's available. `clear_backups` reclaims disk by age.

**6. Project-wide refactors — preview first.** Use `diff_preview` (or `find_in_files` to scope) before `replace_in_files` on a large tree.

**7. Batch when you can.** `batch_read_files` for cross-file context. `batch_copy_files` for multi-file copies. `batch_mysql_schema` / `batch_mysql_queries` / `batch_mysql_queries_with_variables` to avoid Claude round-trips when later steps depend on earlier ones.

**8. SSH state persists across `ssh_send` calls.** `cd`, `export`, and shell history all carry. Use one-shot `ssh_upload`/`ssh_download` when you don't need a session.

**9. PowerShell — prefer `script`.** Inline `script` parameter handles `$variables`, multi-line, and quoting cleanly with no escaping. `parameters` is single-line only.

**10. MySQL — split by result shape.** `mysql_select` for rows, `mysql_execute` for writes, `mysql_scalar` for single values, `mysql_schema` for structure. Run `mysql_test` after editing the connection string.
